## Interview prep

- **Walk through the Shopping Assistant:** the LangGraph graph (nodes, tool calls, conditional routing, bounded retries), where state lives (Postgres checkpointer vs typed facts in PostgreSQL), and why memory is typed facts rather than vectors.
- **Evaluation:** the 12 tasks × 3 runs code-graded suite; prompt v2 went from 7 to 12 of 12 with 29% fewer paid rerank calls; v3 moved price and rating limits inside search (57/81 → 48/48 matching).
- **Retrieval:** hybrid vs keyword vs vector (72% / 56% / 41% top-10 recall on 127 labelled queries), reranking 23% → 43%, HNSW 35 ms → 3.1 ms.
- **Failure handling:** what happens when a tool errors, the model returns invalid JSON (Pydantic validation and retry), or the user tries to plant a false "fact" (memory-write guardrails, 0 of 21 legitimate facts refused).
- **CS foundations (they stress these):** data structures and complexity, a hash map vs a B-tree index, what HNSW does (graph-based approximate nearest neighbours) and why it beat exact search (35 ms → 3.1 ms), threads vs async, and race conditions.
- **LLM mechanics:** context-window limits, tokenisation effects (Arabic text uses more tokens), function-calling protocols, non-determinism (why you ran each task 3 times), and hallucination management.
- **Root-cause story:** tell the 70% → 100% fix as a debugging narrative (symptom, hypothesis, measurement, fix, re-measure).
- **MCP and OpenTelemetry (gap):** know what they are: MCP is a standard way to expose tools and data to models; OpenTelemetry's GenAI conventions standardise traces of model and tool calls.
- **Ask them:** the level they'd place you at, the mentorship setup, and the hybrid policy.
